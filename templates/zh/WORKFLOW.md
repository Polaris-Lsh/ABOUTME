# AboutMe 更新工作流

> 任何 Agent 都按本文件读写。核心一句话：**碎片自动沉淀，全貌逐渐还原，合并不用你催。**

## A. 会话内信息分流（自动）——先判层，再落盘

对话中凡是透露**我这个人**的碎片（随口提到的项目、日程、习惯、偏好、能力），**无需我说"记住"**，自动按下面判据沉淀——档案缺的板块就靠这些碎片逐渐补全。觉察到信息时先过三分流，**一条信息只进一层**；拿不准就留在会话（默认不入档）：

| 判据 | 层 | 动作 |
|---|---|---|
| 只对当前对话 / 当前任务有用（一次性决定、bug 细节、临时上下文） | **会话层** | 不落盘，留在当前会话 |
| 对这个 Agent 本身全局有用（工具用法、环境经验、该平台习惯） | **Agent memory 层** | 写进该 Agent 自带的记忆系统（平台 memory、项目空间），不进本目录 |
| 关于我的**总体事实 / 长期偏好**，或**带明确日期的时效信息**（考试、截止、节点） | **AboutMe 层** | 追加写 `delta.md`（不直接改 `ABOUTME.md`） |

**AboutMe 层的类别**：

- **项目**：新项目启动 / 结束、重大节点变化（只记"有无与层级"，不记项目细节）
- **能力**：新掌握 / 新暴露的知识短板
- **日程**：考试、截止日期、重要节点增删（**必须带日期**）
- **偏好**：协作方式、反感点、语气要求的修正
- **环境**：换设备、换工具
- **修正**：发现 `ABOUTME.md` 写错 / 过时的事实

写法：一行一条，`- [日期] @来源 类别：内容`；时效条目写成 `- [日期] @来源 类别(至 YYYY-MM-DD)：内容`。`@来源` = 你自己(Agent)的名字/平台(如 `@claude`/`@cursor`/`@opencode`)，不确定就写个简短自称——它让 delta 成为一条跨 Agent 时间线，也便于合并时裁决冲突。
**不确定值不值得记就写**，合并时再按判据筛——漏记比多记难补。

> 在项目空间干活时默认不写本目录，你明确要求时除外。

## B. 合并（agent 主动执行，不用等你发话）

**任一条件满足就直接执行下面的流程**，并给一行简报（"已合并 N、丢弃 M"）；
你**要求立即合并**时（opencode 用 `/aboutme merge`，其他场合任意措辞均可，不依赖固定关键词）立即执行并完整汇报：

1. 写入 delta 后发现已攒到 **≥3 条**；
2. 读档案时发现 delta 非空（先合并再读，读到的即全貌）；
3. delta 中有条目已满足其时效期限。

流程：

1. 读 `ABOUTME.md` 全文与 `delta.md` 的待合并条目。
2. 逐条判断，先过三关（保证主档案只有**总体 + 未过期的时效**信息）：
   - **分层关**：其实只对当时会话有用 → 丢弃；属于某 Agent / 工具自身的经验 → 指回该去的地方（平台 memory、项目空间），不入档；
   - **总体关**：一次性决定、项目局部细节 → 不入主档案，需要的话写进项目空间；
   - **时效关**：带日期的条目已过期 → 删除并列入汇报；未过期 → 并入时**保留日期标签**。
   通过三关的：重复 → 丢弃；冲突 → **以新为准改写**（用各条的 `[日期]` 与 `@来源` 判断新旧与出处）并说明改了哪条；新增 → 并入对应章节。
3. 把 `ABOUTME.md` front-matter 的 `updated:` 设为今天。
4. 清空 `delta.md` 的"待合并条目"区（保留模板头）。
5. 汇报：并入 N 条、丢弃 M 条、修正 K 条——**只列条目标题，不复述全文**。

> 合并是**编辑**不是追加：主档案始终保持紧凑、无矛盾、可通读。

## C. 按需读取（新 Agent 认识你）

**先判开关**：当前项目指令或我说了 `AboutMe: off` → 本会话**完全不读不写**档案目录（不读 ABOUTME/delta/本文件其余部分，不写 delta、不合并），后续规则全部跳过；`AboutMe: lite` → 只读 `ABOUTME.md` 的"怎么和我协作"章节，不读 delta、不触发合并。都没说 → 默认 on，按下面走。

**没有开场动作，不自动读。** 只在两种时机：

1. 你**明确要求读档**（任意措辞即可，无需固定关键词；opencode 可用
   `/aboutme read`）→ 读 `ABOUTME.md` + `delta.md` **全文**
   （未合并 delta 是其他 Agent 最近学到的，读完直接当已知事实用）。
2. Agent 需要你的背景 / 协作偏好才能干活 → 只读 `ABOUTME.md` 的"怎么和我协作"章节。

例外：`ABOUTME.md` **仍是种子**（front-matter `updated: never`，触发条件见 `ONBOARDING.md`）→ 不读空档案，
改走 `ONBOARDING.md` 引导问答，收集写入后给出使用说明。

时机 1/2 中发现 delta 非空 → **先按 §B 合并再读**，把"已合并 N、丢弃 M"并进本次汇报。

## 边界

- `delta.md` 是草稿区，允许粗糙；`ABOUTME.md` 是现役档案，只经合并流程改动。
- 秘密（密码 / token / 证件号）**永不写入** `ABOUTME.md` / `delta.md`：听到我给出此类信息，只提醒"这个别进档案"，不代写、不复述（我自己的私人文件由我手动维护）。
- 本工作流本身要改时，先与你讨论再动。
